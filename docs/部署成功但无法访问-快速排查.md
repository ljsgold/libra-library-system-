# 🚨 部署成功但无法访问 - 快速排查指南

## ✅ 确认信息

从你的 Vercel 部署日志来看：
- ✅ **构建成功**：`构建完成于 /vercel/output [30秒]`
- ✅ **部署完成**：`部署完成`
- ✅ **状态 Ready**：部署状态为 "Ready"

**既然部署成功，但出现 `ERR_CONNECTION_TIMED_OUT`，问题可能是：**

---

## 🔍 第一步：确认访问的 URL 是否正确

### 1.1 获取正确的 Vercel 域名

1. 在 Vercel Dashboard 中，进入你的项目：`libra-library-system-mga2`
2. 点击 **"Settings"** → **"General"**
3. 在 **"Domains"** 部分，查看分配的域名

**Vercel 域名格式通常是：**
- `https://libra-library-system-mga2.vercel.app`
- 或者自定义域名（如果你配置了）

### 1.2 测试访问

在浏览器中访问：
```
https://你的-vercel-域名.vercel.app
```

**请告诉我：**
- 你访问的完整 URL 是什么？
- 是直接访问 Vercel 分配的域名，还是自定义域名？

---

## 🔍 第二步：检查环境变量配置

### 2.1 确认环境变量已设置

1. 在 Vercel Dashboard 中，进入 **"Settings"** → **"Environment Variables"**
2. 检查是否存在以下变量：
   - **Name**: `VITE_APP_BASE_API`
   - **Value**: 你的 Railway 后端地址（例如：`https://libra-library-system-production.up.railway.app`）

**请告诉我：**
- 环境变量 `VITE_APP_BASE_API` 是否存在？
- 如果存在，值是什么？

### 2.2 如果环境变量未设置

**立即设置：**

1. 在 Vercel Dashboard 中，进入 **"Settings"** → **"Environment Variables"**
2. 点击 **"Add New"**
3. 填写：
   - **Name**: `VITE_APP_BASE_API`
   - **Value**: 你的 Railway 后端地址（例如：`https://libra-library-system-production.up.railway.app`）
   - **Environment**: 全选（Production, Preview, Development）
4. 点击 **"Save"**
5. **重要**：回到 **"Deployments"** 标签页，找到最新部署，点击 **"..."** → **"Redeploy"**

---

## 🔍 第三步：检查浏览器开发者工具

### 3.1 打开开发者工具

1. 访问你的前端 URL
2. 按 `F12` 打开开发者工具
3. 打开 **"Network"**（网络）标签页
4. 刷新页面

### 3.2 查看请求状态

**请告诉我：**
- `index.html` 的请求状态是什么？（200、404、超时？）
- `assets/*.js` 文件的请求状态是什么？
- `assets/*.css` 文件的请求状态是什么？

**可能的情况：**

#### 情况 A：所有资源都超时
- **原因**：Vercel 域名或 DNS 配置问题
- **解决**：检查 Vercel 域名是否正确，或等待 DNS 传播（最多 24 小时）

#### 情况 B：`index.html` 返回 200，但页面空白
- **原因**：JavaScript 文件加载失败或运行时错误
- **解决**：查看 **"Console"**（控制台）标签页，检查是否有错误

#### 情况 C：所有资源都返回 200，但 API 请求超时
- **原因**：环境变量未配置或后端无法访问
- **解决**：检查 `VITE_APP_BASE_API` 环境变量，并确认后端是否正常运行

---

## 🔍 第四步：检查 Vercel 项目根目录配置

### 4.1 确认根目录设置

1. 在 Vercel Dashboard 中，进入 **"Settings"** → **"General"**
2. 查看 **"Root Directory"** 设置

**请告诉我：**
- **Root Directory** 是 `libra-frontend` 还是 `.`（项目根目录）？

### 4.2 根据根目录检查配置

#### 如果 Root Directory = `libra-frontend`

确保 `libra-frontend/vercel.json` 存在且配置正确：
```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "framework": "vite",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

#### 如果 Root Directory = `.`（项目根目录）

确保根目录的 `vercel.json` 存在且配置正确：
```json
{
  "buildCommand": "cd libra-frontend && npm install && npm run build",
  "outputDirectory": "libra-frontend/dist",
  "framework": "vite",
  "installCommand": "cd libra-frontend && npm install",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

## 💡 常见问题快速解决

### 问题 1：环境变量未配置

**症状**：页面能打开，但 API 请求失败

**解决**：
1. 在 Vercel 中设置 `VITE_APP_BASE_API` 环境变量
2. 重新部署前端

### 问题 2：访问了错误的 URL

**症状**：所有资源都超时

**解决**：
1. 确认访问的是 Vercel 分配的域名（不是 GitHub Pages 或其他）
2. 格式：`https://项目名.vercel.app`

### 问题 3：DNS 未生效

**症状**：域名无法解析

**解决**：
1. 等待最多 24 小时（DNS 传播需要时间）
2. 或使用 Vercel 分配的默认域名

### 问题 4：后端无法访问

**症状**：前端能打开，但所有 API 请求超时

**解决**：
1. 检查 Railway 后端服务状态
2. 确认后端域名是否正确
3. 检查 CORS 配置（代码中已配置允许所有来源）
