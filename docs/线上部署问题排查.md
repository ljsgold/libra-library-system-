# 🔍 线上部署问题排查指南

## ❌ 常见错误：ERR_CONNECTION_TIMED_OUT

这个错误表示前端无法连接到后端服务器。请按照以下步骤逐一检查：

---

## ✅ 第一步：检查后端服务是否正常运行

### 1.1 检查 Railway 后端服务状态

1. 登录 Railway：https://railway.app
2. 进入你的项目
3. 点击后端服务（不是 MySQL 服务）
4. 查看服务状态：
   - ✅ **绿色 "Running"** = 服务正常运行
   - ❌ **红色 "Failed"** 或 **黄色 "Building"** = 服务有问题

### 1.2 检查后端日志

1. 在 Railway 后端服务页面，点击 **"Logs"** 标签页
2. 查看最近的日志，检查是否有错误信息
3. **常见错误**：
   - `Connection refused` = 数据库连接失败
   - `Table doesn't exist` = 数据库未初始化
   - `Port already in use` = 端口冲突

### 1.3 测试后端 API 是否可访问

1. 在 Railway 后端服务页面，点击 **"Settings"** 标签页
2. 在 **"Domains"** 部分，找到你的后端域名（例如：`xxx.railway.app`）
3. 在浏览器中访问：`https://你的后端域名/swagger-ui.html`
4. **如果能看到 Swagger 文档** = 后端正常运行 ✅
5. **如果无法访问或超时** = 后端有问题 ❌

---

## ✅ 第二步：检查 Vercel 环境变量配置

### 2.1 确认环境变量已设置

1. 登录 Vercel：https://vercel.com/dashboard
2. 进入你的前端项目：`libra-library-system-mga2`
3. 点击 **"Settings"** → **"Environment Variables"**
4. 检查是否存在以下变量：
   - **Name**: `VITE_APP_BASE_API`
   - **Value**: 应该是你的 Railway 后端地址（例如：`https://xxx.railway.app`）
   - **Environment**: 应该全选（Production, Preview, Development）

### 2.2 确认环境变量值正确

**重要检查项**：
- ✅ 后端地址必须以 `https://` 开头（不是 `http://`）
- ✅ 后端地址不能有末尾斜杠（例如：`https://xxx.railway.app` ✅，不是 `https://xxx.railway.app/` ❌）
- ✅ 后端地址应该是完整的域名（例如：`https://libra-backend-production.up.railway.app`）

### 2.3 重新部署前端

**环境变量修改后，必须重新部署才能生效！**

1. 在 Vercel Dashboard 中，点击 **"Deployments"** 标签页
2. 找到最新的部署
3. 点击 **"..."** → **"Redeploy"**
4. 等待部署完成（约 1-2 分钟）

---

## ✅ 第三步：检查后端 CORS 配置

后端已经配置了 CORS，允许所有来源访问。如果仍有问题，检查：

1. 在 Railway 后端服务页面，查看 **"Logs"** 标签页
2. 如果看到 CORS 相关错误，说明 CORS 配置可能有问题
3. 检查 `libra-admin/src/main/java/com/libra/admin/config/CorsConfig.java` 文件

---

## ✅ 第四步：验证前后端连接

### 4.1 在浏览器中测试后端 API

1. 打开浏览器开发者工具（F12）
2. 访问你的前端地址
3. 打开 **"Network"**（网络）标签页
4. 尝试执行一个操作（例如：登录、查看图书列表）
5. 查看网络请求：
   - **请求 URL** 应该是：`https://你的后端域名/xxx`
   - **状态码**：
     - `200` = 成功 ✅
     - `404` = 接口不存在
     - `500` = 服务器错误
     - `ERR_CONNECTION_TIMED_OUT` = 无法连接到后端

### 4.2 检查控制台错误

在浏览器开发者工具的 **"Console"**（控制台）标签页中，查看是否有错误信息：
- `Failed to fetch` = 无法连接到后端
- `CORS error` = 跨域问题
- `Network Error` = 网络错误

---

## 🔧 快速修复步骤

如果以上检查都正常，但仍然无法连接，请按以下步骤操作：

### 步骤 1：确认后端地址

1. 在 Railway 中，复制你的后端域名（例如：`libra-backend-production.up.railway.app`）
2. 在浏览器中直接访问：`https://你的后端域名/swagger-ui.html`
3. **如果无法访问** = 后端服务有问题，需要检查 Railway 日志
4. **如果能够访问** = 后端正常，继续下一步

### 步骤 2：更新 Vercel 环境变量

1. 在 Vercel 中，进入 **"Settings"** → **"Environment Variables"**
2. 找到 `VITE_APP_BASE_API` 变量
3. 点击 **"Edit"**（编辑）
4. 确认值为：`https://你的后端域名`（不要有末尾斜杠）
5. 点击 **"Save"**（保存）

### 步骤 3：重新部署前端

1. 在 Vercel Dashboard 中，点击 **"Deployments"** 标签页
2. 点击最新的部署右侧的 **"..."** → **"Redeploy"**
3. 等待部署完成

### 步骤 4：清除浏览器缓存

1. 按 `Ctrl + Shift + Delete`（Windows）或 `Cmd + Shift + Delete`（Mac）
2. 选择清除缓存和 Cookie
3. 重新访问前端地址

## 💡 常见问题解答

### Q: 为什么修改环境变量后还是不行？

**A:** 环境变量修改后，必须重新部署前端才能生效。Vercel 在构建时会读取环境变量，如果只是修改了环境变量但没有重新部署，前端代码中仍然使用的是旧的值。

### Q: 后端地址应该是什么格式？

**A:** 应该是完整的 HTTPS 地址，例如：`https://libra-backend-production.up.railway.app`。注意：
- 必须以 `https://` 开头
- 不能有末尾斜杠 `/`
- 不能包含路径（如 `/api`）

### Q: 为什么直接访问后端可以，但前端无法连接？

**A:** 可能是以下原因：
1. Vercel 环境变量未正确配置
2. 前端未重新部署
3. 浏览器缓存了旧的前端代码
4. CORS 配置问题（但代码中已配置允许所有来源）

### Q: Railway 服务显示 "Running" 但无法访问？

**A:** 可能是：
1. 服务刚启动，还在初始化（等待 1-2 分钟）
2. 端口配置错误（检查 `PORT` 环境变量是否为 `8080`）
3. 域名未生成（需要在 Settings → Domains 中生成域名）
