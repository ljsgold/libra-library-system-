# 🔧 前后端连接问题排查指南

## 🎯 问题现象

- 前端部署在 Vercel，后端部署在 Railway
- 前端无法连接到后端
- 登录时提示"繁忙"或网络错误

---

## ✅ 第一步：检查 Vercel 环境变量配置（最重要！）

### 1.1 获取后端地址

1. **登录 Railway**
   - 访问：https://railway.app
   - 进入你的后端项目

2. **找到后端服务**
   - 点击后端服务（不是 MySQL 服务）
   - 点击 **"Settings"** 标签页
   - 在 **"Domains"** 部分，找到你的后端域名
   - 格式类似：`https://xxx.railway.app` 或 `https://xxx.up.railway.app`

3. **复制完整的后端地址**
   - ✅ 正确格式：`https://libra-backend-production.up.railway.app`
   - ❌ 错误格式：`https://xxx.railway.app/`（不要有末尾斜杠）
   - ❌ 错误格式：`http://xxx.railway.app`（必须是 https）

### 1.2 在 Vercel 中配置环境变量

1. **登录 Vercel Dashboard**
   - 访问：https://vercel.com/dashboard
   - 进入你的前端项目

2. **打开环境变量设置**
   - 点击左侧菜单的 **"Settings"**（设置）
   - 点击 **"Environment Variables"**（环境变量）

3. **检查或添加环境变量**
   - 查找变量名：`VITE_APP_BASE_API`
   - 如果不存在，点击 **"Add New"** 添加
   - 如果存在，点击 **"Edit"** 修改

4. **配置环境变量值**
   - **Name（名称）**：`VITE_APP_BASE_API`
   - **Value（值）**：粘贴你从 Railway 复制的后端地址
     - ✅ 正确：`https://libra-backend-production.up.railway.app`
     - ❌ 错误：`https://xxx.railway.app/`（有末尾斜杠）
     - ❌ 错误：`http://xxx.railway.app`（不是 HTTPS）
     - ❌ 错误：`/api`（开发环境默认值，生产环境不适用）
   - **Environment（环境）**：**全选**（Production、Preview、Development）

5. **保存并重新部署**
   - 点击 **"Save"**（保存）
   - **⚠️ 重要：修改环境变量后，必须重新部署才能生效！**
   - 在 **"Deployments"** 标签页，找到最新部署，点击 **"..."** → **"Redeploy"**

---

## ✅ 第二步：验证后端服务状态

### 2.1 检查后端服务是否运行

1. **在 Railway 后端服务页面**
   - 查看状态指示器：
     - ✅ **绿色 "Running"** = 正常运行
     - ❌ **红色 "Failed"** = 服务失败
     - ⏳ **黄色 "Building"** = 正在构建/重启

2. **如果状态不是 "Running"**
   - 点击 **"Logs"** 标签页
   - 查看最近的错误信息
   - 常见错误：
     - `Connection refused` = 数据库连接失败
     - `Table doesn't exist` = 数据库未初始化
     - `Port already in use` = 端口冲突

### 2.2 测试后端是否可访问

1. **在浏览器中访问后端 Swagger 文档**
   - 访问：`https://你的后端域名/swagger-ui.html`
   - 或者：`https://你的后端域名/swagger-ui/index.html`
   - 如果能看到 Swagger 文档，说明后端正常运行 ✅

2. **测试后端 API**
   - 在 Swagger 文档中，尝试调用一个公开接口（如健康检查接口）
   - 或者直接访问：`https://你的后端域名/actuator/health`

---

## ✅ 第三步：检查浏览器网络请求

### 3.1 打开浏览器开发者工具

1. **访问前端地址**
   - 打开你的 Vercel 前端域名

2. **打开开发者工具**
   - 按 `F12` 或右键点击页面 → **"检查"**
   - 打开 **"Network"**（网络）标签页

3. **尝试登录**
   - 输入用户名和密码
   - 点击登录按钮

### 3.2 查看网络请求

1. **检查请求 URL**
   - 在 Network 标签页中，找到登录相关的 API 请求
   - 查看请求的 URL：
     - ✅ **正确**：`https://你的后端域名/auth/login`
     - ❌ **错误**：`/api/auth/login`（说明环境变量未生效）
     - ❌ **错误**：`https://你的前端域名/api/auth/login`（说明环境变量未生效）

2. **查看请求状态**
   - `200` = 成功 ✅
   - `404` = 接口不存在
   - `500` = 服务器错误
   - `ERR_CONNECTION_TIMED_OUT` = 无法连接到后端
   - `CORS error` = 跨域问题
   - `Failed to fetch` = 网络错误

3. **查看控制台错误**
   - 打开 **"Console"**（控制台）标签页
   - 查看是否有错误信息：
     - `Failed to fetch` = 无法连接到后端
     - `CORS error` = 跨域问题
     - `Network Error` = 网络错误
     - `ERR_CONNECTION_TIMED_OUT` = 连接超时

---

## ✅ 第四步：检查 CORS 配置

后端已经配置了 CORS，允许所有来源访问。如果仍有 CORS 错误：

1. **确认后端 CORS 配置正确**
   - 文件：`libra-admin/src/main/java/com/libra/admin/config/CorsConfig.java`
   - 应该允许所有来源：`config.setAllowedOriginPatterns(List.of("*"));`
   - `allowCredentials` 应该设置为 `false`（因为使用 JWT token，不需要 cookies）

2. **如果 CORS 配置正确但仍有问题**
   - 可能是浏览器缓存问题
   - 清除浏览器缓存后重试
   - 或者使用无痕模式测试

---

## 🔧 快速修复步骤总结

如果以上检查都正常，但仍然无法连接，请按以下步骤操作：

### 步骤 1：确认后端地址
1. 在 Railway 中，复制你的后端域名
2. 在浏览器中直接访问：`https://你的后端域名/swagger-ui.html`
3. 如果无法访问，说明后端服务有问题

### 步骤 2：配置 Vercel 环境变量
1. 在 Vercel 中，添加或修改 `VITE_APP_BASE_API` 环境变量
2. 值应该是：`https://你的后端域名`（没有末尾斜杠）
3. 确保选择了所有环境（Production、Preview、Development）

### 步骤 3：重新部署前端
1. 在 Vercel Dashboard 中，点击 **"Deployments"** 标签页
2. 找到最新的部署
3. 点击右侧的 **"..."** → **"Redeploy"**
4. 等待部署完成（约 1-2 分钟）

### 步骤 4：验证连接
1. 访问前端地址
2. 打开浏览器开发者工具（F12）
3. 尝试登录
4. 在 Network 标签页中，检查请求 URL 是否正确指向后端地址

## 📝 常见问题

### Q1: 环境变量配置后仍然无法连接？
**A:** 确保已经重新部署了前端。环境变量只在构建时生效，修改后必须重新部署。

### Q2: 后端可以访问 Swagger，但前端无法连接？
**A:** 检查 Vercel 环境变量配置，确保 `VITE_APP_BASE_API` 的值是正确的后端地址。

### Q3: 出现 CORS 错误？
**A:** 后端已经配置了 CORS，允许所有来源。如果仍有问题，可能是浏览器缓存，尝试清除缓存或使用无痕模式。

### Q4: 登录时提示"繁忙"？
**A:** 这通常是因为前端无法连接到后端。检查：
1. 后端服务是否正常运行
2. Vercel 环境变量是否正确配置
3. 浏览器网络请求中的错误信息
