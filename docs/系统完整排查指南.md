# 🔍 系统完整排查指南（国内网络可用版）

## 📋 系统架构概览

```
前端 (Vercel) 
    ↓ (通过 VITE_APP_BASE_API 环境变量)
后端 API (Railway)
    ↓ (通过环境变量连接)
MySQL 数据库 (Railway)
```

**关键配置点**：
- 前端地址：Vercel 分配的域名（例如：`xxx.vercel.app`）
- 后端地址：Railway 分配的域名（例如：`xxx.railway.app`）
- 连接方式：前端通过 `VITE_APP_BASE_API` 环境变量连接后端

---

## ✅ 第一步：检查后端服务（Railway）

### 1.1 检查后端服务状态

1. **登录 Railway**
   - 访问：https://railway.app
   - 进入你的项目

2. **查看服务状态**
   - 找到后端服务（不是 MySQL 服务）
   - 查看状态指示器：
     - ✅ **绿色 "Running"** = 正常运行
     - ❌ **红色 "Failed"** = 服务失败
     - ⏳ **黄色 "Building"** = 正在构建/重启

3. **如果状态不是 "Running"**
   - 点击服务，查看 **"Logs"** 标签页
   - 查看最近的错误信息
   - 常见错误：
     - `Connection refused` = 数据库连接失败
     - `Table doesn't exist` = 数据库未初始化
     - `Port already in use` = 端口冲突

### 1.2 获取后端地址

1. **在 Railway 后端服务页面**
   - 点击 **"Settings"** 标签页
   - 找到 **"Domains"** 部分
   - 查看你的后端域名（例如：`libra-backend-production.up.railway.app`）

2. **如果看不到域名**
   - 点击 **"Generate Domain"** 按钮
   - 等待几秒钟，域名会自动生成

3. **记录后端地址**
   - 完整格式：`https://你的后端域名`
   - 示例：`https://libra-backend-production.up.railway.app`
   - ⚠️ **重要**：不要有末尾斜杠 `/`

### 1.3 测试后端是否可访问

1. **在浏览器中访问后端 Swagger 文档**
   - 地址：`https://你的后端域名/swagger-ui.html`
   - 例如：`https://libra-backend-production.up.railway.app/swagger-ui.html`

2. **检查结果**：
   - ✅ **能看到 Swagger 文档** = 后端正常运行
   - ❌ **无法访问或超时** = 后端有问题

3. **如果无法访问**：
   - 检查 Railway 服务状态（回到 1.1）
   - 查看 Railway 日志（Logs 标签页）
   - 确认域名已生成（回到 1.2）

### 1.4 检查后端环境变量

1. **在 Railway 后端服务页面**
   - 点击 **"Variables"** 标签页
   - 检查以下关键变量：

2. **数据库连接变量**（Railway 自动提供）：
   ```
   MYSQLHOST=${{MySQL.MYSQLHOST}}
   MYSQLPORT=${{MySQL.MYSQLPORT}}
   MYSQLDATABASE=${{MySQL.MYSQLDATABASE}}
   MYSQLUSER=${{MySQL.MYSQLUSER}}
   MYSQLPASSWORD=${{MySQL.MYSQLPASSWORD}}
   ```

3. **端口变量**：
   ```
   PORT=8080
   ```

4. **如果缺少变量**：
   - 点击 **"New Variable"** 添加
   - 使用 `${{MySQL.XXX}}` 格式引用 MySQL 服务变量

## ✅ 第二步：检查前端服务（Vercel）

### 2.1 检查前端部署状态

1. **登录 Vercel**
   - 访问：https://vercel.com/dashboard
   - 进入你的项目

2. **查看部署状态**
   - 点击 **"Deployments"** 标签页
   - 查看最新部署的状态：
     - ✅ **Ready** = 部署成功
     - ❌ **Error** = 部署失败
     - ⏳ **Building** = 正在构建

3. **如果部署失败**
   - 点击失败的部署，查看错误日志
   - 常见错误：
     - 构建命令错误
     - 依赖安装失败
     - 环境变量未设置

### 2.2 获取前端地址

1. **在 Vercel 项目页面**
   - 查看 **"Domains"** 部分
   - 找到你的前端地址（例如：`xxx.vercel.app`）

2. **测试前端是否可访问**
   - 在浏览器中访问前端地址
   - 检查是否能打开登录页面

3. **如果无法访问**
   - 检查部署状态（回到 2.1）
   - 查看部署日志

### 2.3 检查前端环境变量（最重要！）

1. **在 Vercel 项目页面**
   - 点击 **"Settings"** → **"Environment Variables"**

2. **检查关键变量 `VITE_APP_BASE_API`**
   - **Name**: `VITE_APP_BASE_API`
   - **Value**: 应该是你的 Railway 后端地址
   - **Environment**: 应该全选（Production, Preview, Development）

3. **验证环境变量值格式**
   - ✅ **正确格式**：`https://libra-backend-production.up.railway.app`
   - ❌ **错误格式 1**：`https://libra-backend-production.up.railway.app/`（有末尾斜杠）
   - ❌ **错误格式 2**：`http://libra-backend-production.up.railway.app`（不是 HTTPS）
   - ❌ **错误格式 3**：`/api`（开发环境默认值，生产环境不适用）

4. **如果环境变量不存在或错误**
   - 点击 **"Add New"** 添加新变量
   - 或者点击现有变量旁边的 **"Edit"** 修改
   - **重要**：修改后必须重新部署前端！

### 2.4 重新部署前端（如果修改了环境变量）

**⚠️ 重要：修改环境变量后，必须重新部署才能生效！**

1. **在 Vercel Dashboard**
   - 点击 **"Deployments"** 标签页
   - 找到最新的部署
   - 点击右侧的 **"..."** → **"Redeploy"**
   - 等待部署完成（约 1-2 分钟）

2. **验证部署**
   - 等待部署状态变为 **"Ready"**
   - 访问前端地址，测试功能

## ✅ 第三步：验证前后端连接

### 3.1 在浏览器中测试

1. **打开浏览器开发者工具**
   - 按 `F12` 或右键点击页面 → **"检查"**
   - 打开 **"Network"**（网络）标签页

2. **访问前端地址**
   - 尝试执行一个操作（例如：登录、查看图书列表）

3. **查看网络请求**
   - 在 Network 标签页中，找到 API 请求
   - 查看请求的 URL：
     - ✅ **正确**：`https://你的后端域名/xxx`
     - ❌ **错误**：`/api/xxx`（说明环境变量未生效）

4. **查看请求状态**
   - `200` = 成功 ✅
   - `404` = 接口不存在
   - `500` = 服务器错误
   - `ERR_CONNECTION_TIMED_OUT` = 无法连接到后端
   - `CORS error` = 跨域问题

### 3.2 检查浏览器控制台

1. **打开浏览器开发者工具**
   - 点击 **"Console"**（控制台）标签页

2. **查看错误信息**
   - `Failed to fetch` = 无法连接到后端
   - `CORS error` = 跨域问题（但后端已配置允许所有来源）
   - `Network Error` = 网络错误
   - `ERR_CONNECTION_TIMED_OUT` = 连接超时

### 3.3 检查 CORS 配置

后端已经配置了 CORS，允许所有来源访问。如果仍有 CORS 错误：

1. **检查后端 CORS 配置**
   - 文件：`libra-admin/src/main/java/com/libra/admin/config/CorsConfig.java`
   - 应该允许所有来源：`config.setAllowedOriginPatterns(List.of("*"));`

2. **如果 CORS 配置正确但仍有问题**
   - 可能是浏览器缓存问题
   - 清除浏览器缓存后重试

## ✅ 第四步：检查数据库连接

### 4.1 检查 MySQL 服务状态

1. **在 Railway 项目页面**
   - 找到 MySQL 服务（不是后端服务）
   - 查看服务状态：
     - ✅ **Running** = 正常运行
     - ❌ **Failed** = 服务失败

### 4.2 检查数据库是否已初始化

1. **在 Railway MySQL 服务页面**
   - 点击 **"Data"** 标签页
   - 查看是否有数据表

2. **如果数据库为空**
   - 需要执行初始化 SQL 脚本
   - 参考：`docs/快速部署.md` 中的数据库初始化步骤

### 4.3 检查后端日志中的数据库连接

1. **在 Railway 后端服务页面**
   - 点击 **"Logs"** 标签页
   - 查看是否有数据库连接错误：
     - `Connection refused` = 数据库连接失败
     - `Access denied` = 数据库认证失败
     - `Unknown database` = 数据库不存在

### 5.1 检查后端域名解析

1. **使用命令行工具**
   ```powershell
   # Windows PowerShell
   nslookup your-backend-domain.railway.app
   ```

2. **使用在线工具**
   - 访问：https://dnschecker.org
   - 输入后端域名
   - 查看 DNS 解析结果

### 5.2 检查前端域名解析

1. **使用命令行工具**
   ```powershell
   nslookup your-frontend-domain.vercel.app
   ```

2. **如果使用自定义域名**
   - 检查 DNS 配置是否正确
   - 参考：`docs/Vercel自定义域名配置排查.md`

### 5.3 检查网络连接

1. **测试后端连接**
   - 在浏览器中直接访问：`https://你的后端域名/swagger-ui.html`
   - 如果无法访问，可能是：
     - 网络问题（国内网络可能无法访问 Railway）
     - DNS 解析问题
     - Railway 服务问题

2. **测试前端连接**
   - 在浏览器中访问前端地址
   - 如果无法访问，可能是：
     - Vercel 部署问题
     - DNS 解析问题
     - 网络问题

## 🔧 快速修复方案

### 方案 1：后端无法访问（国内网络问题）

**症状**：后端 Railway 地址在国内无法访问

**解决方案**：
1. **使用代理/VPN**（临时方案）
2. **使用国内云服务商部署后端**（长期方案）
   - 阿里云 ECS
   - 腾讯云 CVM
   - 参考：`docs/国内网络访问解决方案.md`

### 方案 2：前端环境变量未生效

**症状**：前端请求仍然使用 `/api`，而不是后端地址

**解决方案**：
1. **检查 Vercel 环境变量**
   - 确认 `VITE_APP_BASE_API` 已设置
   - 确认值格式正确（`https://xxx.railway.app`，无末尾斜杠）

2. **重新部署前端**
   - 在 Vercel Dashboard → Deployments → Redeploy

3. **清除浏览器缓存**
   - 按 `Ctrl + Shift + Delete`
   - 清除缓存和 Cookie

### 方案 3：后端服务启动失败

**症状**：Railway 后端服务状态为 "Failed"

**解决方案**：
1. **查看 Railway 日志**
   - 找到错误信息
   - 常见问题：
     - 数据库连接失败 → 检查环境变量
     - 数据库未初始化 → 执行 SQL 脚本
     - 端口冲突 → 检查 PORT 环境变量

2. **检查环境变量**
   - 确认数据库连接变量已设置
   - 确认使用 `${{MySQL.XXX}}` 格式

3. **重新部署**
   - 在 Railway 中，点击服务 → **"Redeploy"**

### 方案 4：前后端连接超时

**症状**：前端能打开，但所有 API 请求超时

**解决方案**：
1. **确认后端地址正确**
   - 在 Vercel 环境变量中，确认 `VITE_APP_BASE_API` 值正确

2. **测试后端是否可访问**
   - 直接访问：`https://你的后端域名/swagger-ui.html`
   - 如果无法访问，后端有问题

3. **检查 CORS 配置**
   - 后端已配置允许所有来源，通常不是 CORS 问题

4. **检查网络**
   - 如果后端在国内无法访问，考虑使用代理或迁移到国内云服务商

## 💡 常见问题 FAQ

### Q1: 之前能访问，现在不能了？

**A**: 可能的原因：
1. Railway 服务重启，域名可能变化
2. Vercel 环境变量被重置
3. 网络环境变化（国内网络可能无法访问 Railway）

**解决方案**：
1. 检查 Railway 后端地址是否变化
2. 更新 Vercel 环境变量
3. 重新部署前端

### Q2: 为什么国内网络无法访问 Railway？

**A**: Railway 的服务器在国外，国内网络可能无法直接访问。

**解决方案**：
1. 使用代理/VPN（临时）
2. 迁移到国内云服务商（长期）
3. 参考：`docs/国内网络访问解决方案.md`

### Q3: 环境变量修改后为什么不生效？

**A**: Vercel 在构建时读取环境变量，修改后必须重新部署。

**解决方案**：
1. 修改环境变量后，在 Deployments 页面点击 "Redeploy"
2. 等待部署完成（约 1-2 分钟）

### Q4: 后端地址应该是什么格式？

**A**: 完整格式：`https://你的后端域名`

**示例**：
- ✅ `https://libra-backend-production.up.railway.app`
- ❌ `https://libra-backend-production.up.railway.app/`（有末尾斜杠）
- ❌ `http://libra-backend-production.up.railway.app`（不是 HTTPS）

### Q5: 如何确认前后端连接正常？

**A**: 
1. 打开浏览器开发者工具（F12）
2. 访问前端，执行一个操作（如登录）
3. 在 Network 标签页中，查看 API 请求：
   - 请求 URL 应该是后端地址
   - 状态码应该是 `200`
