# 🌐 国内网络访问 Vercel 解决方案

## 🎯 问题说明

**症状**：
- ✅ 使用 VPN 连接境外网络后，可以正常访问前端页面
- ❌ 切换回国内网络后，无法访问（`ERR_CONNECTION_TIMED_OUT`）

**原因**：
- 国内网络可能对 Vercel 的域名或 IP 地址进行了限制
- DNS 解析可能不稳定
- Vercel 的 CDN 节点在国内访问可能较慢或不稳定

---

## 🚀 解决方案（按推荐程度排序）

### 方案一：使用国内部署平台（推荐 ⭐⭐⭐⭐⭐）

**优点**：
- ✅ 国内访问速度快
- ✅ 无需 VPN
- ✅ 免费或低成本
- ✅ 配置简单

**可选平台**：

#### 1.1 使用 Vercel 中国版（如果可用）

目前 Vercel 没有官方中国版，但可以考虑其他平台。

#### 1.2 使用 Netlify（推荐）

Netlify 在国内访问相对稳定，且配置与 Vercel 类似。

**部署步骤**：

1. **注册 Netlify 账号**
   - 访问：https://www.netlify.com
   - 使用 GitHub 账号登录

2. **导入项目**
   - 点击 **"Add new site"** → **"Import an existing project"**
   - 选择你的 GitHub 仓库
   - 配置：
     - **Base directory**: `libra-frontend`
     - **Build command**: `npm run build`
     - **Publish directory**: `dist`

3. **配置环境变量**
   - 进入 **"Site settings"** → **"Environment variables"**
   - 添加：`VITE_APP_BASE_API` = `你的后端地址`

4. **部署**
   - 点击 **"Deploy site"**
   - 等待部署完成

#### 1.3 使用 Cloudflare Pages（推荐 ⭐⭐⭐⭐⭐）

Cloudflare Pages 在国内访问相对稳定，且完全免费。

**部署步骤**：

1. **注册 Cloudflare 账号**
   - 访问：https://pages.cloudflare.com
   - 使用 GitHub 账号登录

2. **创建项目**
   - 点击 **"Create a project"**
   - 选择你的 GitHub 仓库
   - 配置：
     - **Project name**: `libra-frontend`
     - **Production branch**: `main` 或 `master`
     - **Build command**: `npm run build`
     - **Build output directory**: `dist`
     - **Root directory**: `libra-frontend`

3. **配置环境变量**
   - 进入 **"Settings"** → **"Environment variables"**
   - 添加：`VITE_APP_BASE_API` = `你的后端地址`

4. **部署**
   - 点击 **"Save and Deploy"**
   - 等待部署完成

#### 1.4 使用国内云服务商（适合有预算的情况）

**可选平台**：
- **阿里云 OSS + CDN**：静态网站托管
- **腾讯云 COS + CDN**：静态网站托管
- **华为云 OBS + CDN**：静态网站托管
- **七牛云**：对象存储 + CDN

**优点**：
- ✅ 国内访问速度最快
- ✅ 稳定性高
- ✅ 支持自定义域名

**缺点**：
- ❌ 需要付费（通常有免费额度）
- ❌ 配置相对复杂

### 方案二：配置自定义域名 + CDN（推荐 ⭐⭐⭐⭐）

**优点**：
- ✅ 可以继续使用 Vercel
- ✅ 通过 CDN 加速，国内访问更快
- ✅ 可以使用自己的域名

**步骤**：

#### 2.1 购买域名（如果还没有）

推荐域名注册商：
- **阿里云**：https://wanwang.aliyun.com
- **腾讯云**：https://dnspod.cloud.tencent.com
- **Cloudflare**：https://www.cloudflare.com/products/registrar

#### 2.2 在 Vercel 中添加自定义域名

1. 在 Vercel Dashboard 中，进入项目 → **"Settings"** → **"Domains"**
2. 点击 **"Add Domain"**
3. 输入你的域名（例如：`libra.example.com`）
4. 按照提示配置 DNS 记录

#### 2.3 配置 CDN（可选，但推荐）

**使用 Cloudflare CDN**（免费）：

1. **注册 Cloudflare 账号**
   - 访问：https://www.cloudflare.com
   - 免费注册

2. **添加网站**
   - 点击 **"Add a Site"**
   - 输入你的域名
   - 按照提示配置 DNS

3. **配置 DNS 记录**
   - 添加 CNAME 记录：
     - **Name**: `@` 或 `www`
     - **Target**: `cname.vercel-dns.com`
     - **Proxy status**: 开启（橙色云朵）

4. **启用 CDN 加速**
   - Cloudflare 会自动启用 CDN
   - 国内访问会通过 Cloudflare 的节点加速

**使用阿里云 CDN**（付费，但速度快）：

1. 在阿里云控制台，开通 CDN 服务
2. 添加加速域名
3. 配置源站为 Vercel 的域名
4. 配置 CNAME 记录指向 CDN 域名

### 方案三：使用代理或镜像（临时方案 ⭐⭐）

**优点**：
- ✅ 无需修改部署配置
- ✅ 快速解决访问问题

**缺点**：
- ❌ 需要用户手动配置
- ❌ 不是长期解决方案

#### 3.1 修改本地 DNS

**Windows**：
1. 打开 `C:\Windows\System32\drivers\etc\hosts` 文件（需要管理员权限）
2. 添加以下行（将 `your-vercel-domain.vercel.app` 替换为你的实际域名）：
```
# Vercel 域名映射（使用可访问的 IP）
your-vercel-domain.vercel.app  151.101.1.195
```

**注意**：这种方法可能不稳定，因为 Vercel 使用 CDN，IP 地址可能变化。

#### 3.2 使用代理工具

- **Clash for Windows**：配置规则，自动代理 Vercel 域名
- **V2Ray**：配置路由规则
- **Shadowsocks**：全局代理

### 方案四：使用 GitHub Pages（备选方案 ⭐⭐⭐）

**优点**：
- ✅ 完全免费
- ✅ 国内访问相对稳定
- ✅ 配置简单

**缺点**：
- ❌ 不支持服务端渲染（但你的项目是静态页面，没问题）
- ❌ 构建需要 GitHub Actions

**部署步骤**：

1. **创建 GitHub Actions 工作流**

在项目根目录创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v3

      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'

      - name: Install dependencies
        run: |
          cd libra-frontend
          npm install

      - name: Build
        run: |
          cd libra-frontend
          npm run build
        env:
          VITE_APP_BASE_API: ${{ secrets.VITE_APP_BASE_API }}

      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./libra-frontend/dist
```

2. **配置 GitHub Secrets**

在 GitHub 仓库中，进入 **"Settings"** → **"Secrets and variables"** → **"Actions"**：
- 添加 `VITE_APP_BASE_API` = `你的后端地址`

3. **启用 GitHub Pages**

在 GitHub 仓库中，进入 **"Settings"** → **"Pages"**：
- **Source**: 选择 `gh-pages` 分支
- **Folder**: 选择 `/ (root)`

4. **触发部署**

推送代码到 `main` 分支，GitHub Actions 会自动构建并部署。

## 🚀 快速开始（推荐：Cloudflare Pages）

### 第一步：准备

1. 确保你的代码已推送到 GitHub
2. 准备好后端地址（Railway 地址）

### 第二步：部署到 Cloudflare Pages

1. **访问 Cloudflare Pages**
   - 打开：https://pages.cloudflare.com
   - 使用 GitHub 账号登录

2. **创建项目**
   - 点击 **"Create a project"**
   - 选择你的 GitHub 仓库
   - 配置：
     - **Project name**: `libra-frontend`
     - **Production branch**: `main`
     - **Framework preset**: `Vite`
     - **Build command**: `npm run build`
     - **Build output directory**: `dist`
     - **Root directory**: `libra-frontend`

3. **配置环境变量**
   - 在构建配置页面，点击 **"Environment variables"**
   - 添加：
     - **Variable name**: `VITE_APP_BASE_API`
     - **Value**: `你的后端地址`（例如：`https://libra-library-system-production.up.railway.app`）

4. **部署**
   - 点击 **"Save and Deploy"**
   - 等待约 2-3 分钟，部署完成

5. **获取访问地址**
   - 部署完成后，你会得到一个地址，格式类似：`https://libra-frontend.pages.dev`
   - 这个地址在国内应该可以正常访问

### 第三步：测试

1. 在国内网络环境下，访问 Cloudflare Pages 分配的地址
2. 测试登录、注册等功能
3. 如果一切正常，说明部署成功！

## 🔧 如果 Cloudflare Pages 也无法访问

如果 Cloudflare Pages 在国内也无法访问，建议使用**国内云服务商**：

### 使用阿里云 OSS + CDN（示例）

1. **开通阿里云 OSS**
   - 访问：https://oss.console.aliyun.com
   - 创建 Bucket（存储桶）

2. **配置静态网站托管**
   - 在 Bucket 设置中，启用 **"静态网站托管"**
   - 设置默认首页为 `index.html`
   - 设置错误页面为 `index.html`（用于 Vue Router）

3. **上传文件**
   - 在本地执行 `npm run build`
   - 将 `libra-frontend/dist` 目录下的所有文件上传到 OSS

4. **配置 CDN**
   - 在阿里云 CDN 控制台，添加加速域名
   - 源站设置为 OSS 的 Bucket 域名
   - 配置 CNAME 记录

5. **配置环境变量**
   - 在构建时，需要设置 `VITE_APP_BASE_API` 环境变量
   - 或者在代码中直接配置（不推荐，但可行）

---

## 📝 注意事项

1. **环境变量配置**
   - 无论使用哪个平台，都需要配置 `VITE_APP_BASE_API` 环境变量
   - 修改环境变量后，需要重新部署

2. **后端 CORS 配置**
   - 确保后端允许新域名的跨域请求
   - 检查 `CorsConfig.java` 中的 `allowedOrigins` 配置

3. **测试**
   - 部署后，在不同网络环境下测试访问
   - 检查 API 请求是否正常
