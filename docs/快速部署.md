# ⚡ 5分钟快速部署指南

## 🎯 目标
将后端部署到 Railway（免费），前端已部署到 Vercel。

---

## 💡 快速理解（重要！）

### ❓ 我需要做什么？

**简单来说，你只需要：**
1. 在 Railway 上创建项目（连接 GitHub）
2. 添加一个 MySQL 数据库（Railway 会自动创建）
3. 配置几个环境变量（告诉后端如何连接数据库）
4. 执行一次 SQL 脚本（创建数据表）
5. 完成！

### ❓ 需要本地连接 MySQL 吗？

**不需要！** 你完全不需要：
- ❌ 在本地安装 MySQL
- ❌ 在本地运行数据库
- ❌ 手动连接数据库

**Railway 会在云端自动：**
- ✅ 创建和管理 MySQL 数据库
- ✅ 提供数据库连接信息
- ✅ 处理所有数据库连接

你只需要在 Railway 网页上点击几个按钮，配置一些环境变量就可以了！

### 🔄 整个流程是怎么工作的？

```
1. 连接 GitHub 仓库 → Railway 开始部署（此时会失败，因为没有数据库）
    ↓
2. 添加 MySQL 数据库 → Railway 自动创建数据库服务（独立运行）
    ↓
3. 执行 SQL 脚本 → 直接连接 MySQL 服务，创建数据表（不需要后端运行）
    ↓
4. 配置环境变量 → 告诉后端如何连接数据库
    ↓
5. Railway 自动重新部署 → 后端成功启动，连接到已初始化的数据库
    ↓
完成！应用可以正常使用了
```

**💡 关键理解**：
- MySQL 数据库服务是**独立的**，创建后就可以直接使用
- 不需要等后端部署成功，就可以执行 SQL 脚本
- 先初始化数据库，后端启动时才能正常工作

## 🚀 详细步骤

### 1️⃣ 注册并登录 Railway

访问：https://railway.app
- 点击 "Login" → 选择 "Login with GitHub"
- 授权 Railway 访问你的 GitHub

### 2️⃣ 创建新项目

**详细步骤：**

1. 登录 Railway 后，在首页（Dashboard）你会看到：
   - 左侧有一个 **"New Project"** 按钮（通常在页面左上角或中间）
   - 或者点击页面中间的 **"New Project"** 卡片

2. 点击 **"New Project"** 后，会弹出选项：
   - **"Deploy from GitHub repo"** ← 选择这个
   - 或者 **"Empty Project"**（不要选这个）

3. 选择 **"Deploy from GitHub repo"** 后：
   - Railway 会显示你的 GitHub 仓库列表
   - 找到并点击你的仓库：`libra-library-system-`（或你的仓库名称）
   - 如果看不到仓库，可能需要先授权 Railway 访问 GitHub

4. 选择仓库后：
   - Railway 会自动开始部署（你会看到部署进度）
   - **⚠️ 此时部署会失败是正常的！** 因为：
     - 还没有添加 MySQL 数据库
     - 还没有配置环境变量
   - **不用担心**，我们接下来会：
     1. 先添加 MySQL 数据库
     2. 先执行 SQL 脚本初始化数据库
     3. 然后配置环境变量
     4. 最后后端会自动重新部署并成功

**💡 关于 Docker：你不需要本地安装 Docker！**

Railway 会在**云端自动**使用 Dockerfile 构建和运行你的应用。你只需要：
- ✅ 确保代码仓库中有 `Dockerfile` 文件（已存在）
- ✅ 确保 Railway 使用 Dockerfile 构建器（见下方检查步骤）

**⚠️ 重要：确保使用 Dockerfile 构建器**

如果构建失败或没有日志，请检查：
1. 点击你的服务 → **"Settings"** 标签页
2. 在 **"Build"** 部分，确认 **"Builder"** 选择的是 **"Dockerfile"**
3. 如果显示的是 "Nixpacks" 或其他，请：
   - 点击 **"Change Builder"**
   - 选择 **"Dockerfile"**
   - 确认 **"Dockerfile Path"** 是 `Dockerfile`
   - 点击 **"Save"**
4. 保存后，Railway 会自动重新部署

**📝 提示：** 项目根目录已经有 `railway.json` 配置文件，理论上 Railway 会自动识别使用 Dockerfile。但如果第一次部署时没有正确识别，请按照上述步骤手动设置。

### 3️⃣ 添加 MySQL 数据库

**这一步很简单，Railway 会自动创建数据库，你不需要做任何配置！**

**详细步骤：**

1. **找到 "+ New" 按钮**：
   - 在 Railway 项目页面中，你会看到已经有一个服务（你的 GitHub 仓库）
   - 在页面的**右上角**或**服务列表的右侧**，有一个 **"+ New"** 按钮（通常是蓝色或绿色的加号按钮）
   - 点击这个按钮

2. **选择数据库类型**：
   - 点击 **"+ New"** 后，会弹出一个菜单或选项列表
   - 你会看到几个选项：
     - **"Database"** ← 点击这个
     - 或者直接看到 **"Add MySQL"** 选项
   - 如果点击了 **"Database"**，会再显示数据库类型选择：
     - **"Add MySQL"** ← 选择这个
     - 或者 **"Add PostgreSQL"**（不要选这个）

3. **等待创建完成**：
   - 选择 **"Add MySQL"** 后，Railway 会自动开始创建数据库
   - 你会看到一个新的服务出现在项目列表中，名称类似 "MySQL" 或 "mysql"
   - 等待约 30 秒，直到状态显示为 **"Running"**（绿色）

**✅ 完成！** Railway 已经自动创建了一个 MySQL 数据库，并准备好了连接信息。

**💡 重要理解**：
- MySQL 数据库服务是**独立运行**的，不需要后端服务运行
- 即使后端服务部署失败，MySQL 服务也可以正常使用
- 你现在就可以连接 MySQL 并执行 SQL 脚本，不需要等后端部署成功

**💡 提示**：如果你找不到 **"+ New"** 按钮，也可以：
- 在项目页面顶部，可能有一个 **"Add Service"** 或 **"New"** 按钮
- 或者点击项目名称旁边的下拉菜单，选择 **"Add Service"**

### 4️⃣ 初始化数据库（先执行这一步！）

**⚠️ 重要：先执行 SQL 脚本初始化数据库，然后再配置环境变量！**

**为什么可以先执行 SQL 脚本？**
- ✅ MySQL 数据库服务已经创建好了，是**独立运行**的
- ✅ 即使后端服务部署失败，MySQL 服务也可以正常使用
- ✅ 执行 SQL 脚本只需要连接到 MySQL 服务，**不需要后端服务运行**
- ✅ 先创建好数据表，后端服务启动时才能正常工作

**这一步是创建数据表。你只需要执行一次 SQL 脚本即可！**

**📁 SQL 脚本文件位置**：
- 初始化脚本：`db/init.sql`（创建所有数据表）← **必须先执行这个**
- 测试数据：`db/seed.sql`（可选，添加测试数据）

**📍 如何找到 SQL 脚本文件？**
1. 在你的项目文件夹中（`E:\图书管理系统`），找到 `db` 文件夹
2. 打开 `db/init.sql` 文件（这是初始化脚本，包含所有表结构）
3. 如果需要测试数据，可以打开 `db/seed.sql` 文件（可选）

#### 🎯 方法一：通过 Railway Web 界面执行 SQL（最简单，推荐！）

**如果你在 Railway 的 MySQL 服务页面看到了"数据库"标签页，可以使用这个方法：**

**详细步骤：**

1. **打开 MySQL 服务页面**：
   - 在 Railway 项目页面中，点击 **MySQL** 数据库服务
   - 你会看到几个标签页：**"部署"**、**"数据库"**、**"备份"**、**"变量"** 等

2. **找到 SQL 执行界面**：
   - 点击 **"数据库"** 标签页
   - 如果看到 **"数据"** 和 **"配置"** 子标签，点击 **"数据"** 标签
   - 查找是否有 **"SQL 查询"**、**"Query"**、**"执行 SQL"** 或类似的按钮/输入框
   - 或者点击 **"连接"** 按钮，查看是否有 Web SQL 编辑器

3. **执行 SQL 脚本**：
   - 打开项目中的 `db/init.sql` 文件
   - **复制全部内容**（按 `Ctrl + A` 全选，然后 `Ctrl + C` 复制）
   - 在 Railway 的 SQL 编辑器中粘贴并执行
   - 等待执行完成

4. **（可选）添加测试数据**：
   - 打开 `db/seed.sql` 文件
   - 复制全部内容
   - 在 SQL 编辑器中粘贴并执行

**💡 提示**：如果 Railway 界面中没有找到 SQL 编辑器，请使用方法二（命令行）或方法三（客户端工具）。

#### 🔧 方法二：使用 Railway 的 MySQL 命令行（推荐，如果 Web 界面不可用）

**详细步骤：**

**第一步：找到 MySQL 服务**

1. 在 Railway 项目页面中，你会看到两个服务：
   - 一个是你的 GitHub 仓库（后端服务）
   - 一个是 **MySQL** 数据库服务（名称可能是 "MySQL"、"mysql" 或类似）
2. **点击 MySQL 数据库服务**（不要点击后端服务）

**第二步：打开连接页面**

3. 点击 MySQL 服务后，你会看到几个标签页：
   - **"部署"**（Deployment）
   - **"数据库"**（Database）
   - **"备份"**（Backup）
   - **"变量"**（Variables）
   - **"指标"**（Metrics）
   - **"连接"** ← **点击这个标签页**（或 **"Connect"**）
4. 点击 **"连接"** 标签页后，会弹出一个连接窗口

**第三步：选择连接方式并复制命令**

5. 在连接窗口中，你会看到两个选项：
   - **"专用网络"**（Private Network）- 免费，但只能从 Railway 内部访问
   - **"公共网络"**（Public Network）- 可以从外部访问，但可能产生费用
6. **选择 "公共网络"** 标签页（因为你要从本地电脑连接）
7. 你会看到三种连接方式：
   - **连接网址**：`mysql://root:********@xxx.proxy.rlwy.net:xxxxx/railway`
   - **原始命令 `mysql`**：`mysql -h xxx.proxy.rlwy.net -u root -p ******** --port xxxxx --protocol=TCP`
   - **Railway CLI 命令**：`railway connect MySQL`
8. **找到 "原始命令 `mysql`" 部分**，点击旁边的**复制图标**（📋）复制命令
   - 注意：命令中的密码部分可能显示为 `********`，你需要手动替换为实际密码

**第四步：在本地终端执行命令**

8. 打开你电脑的**终端/命令行**：
   - **Windows**：按 `Win + R`，输入 `powershell` 或 `cmd`，回车
   - **Mac**：按 `Cmd + Space`，输入 `terminal`，回车
   - **Linux**：按 `Ctrl + Alt + T`
9. 在终端中，**粘贴刚才复制的命令**（按 `Ctrl + V` 或右键粘贴），然后按回车
10. **获取密码**：
    - 回到 Railway 的 **"连接"** 标签页
    - 在连接窗口中，找到密码字段（可能在连接网址中，或者有单独的密码显示）
    - 如果密码显示为 `********`，你需要：
      - 查看 MySQL 服务的 **"变量"**（Variables）标签页
      - 找到 `MYSQL_ROOT_PASSWORD` 变量，复制其值
    - 或者，如果命令中有 `-p ********`，将 `********` 替换为实际密码
11. **执行连接命令**：
    - 如果命令中包含 `-p ********`，将 `********` 替换为实际密码后执行
    - 或者，如果命令是 `mysql -h ... -u root -p`（没有密码），执行后提示输入密码时：
      - 粘贴刚才复制的密码（粘贴时不会显示任何字符，这是正常的）
      - 按回车
11. 连接成功后，你会看到 `mysql>` 提示符，类似这样：
    ```
    Welcome to the MySQL monitor.  Commands end with ; or \g.
    mysql>
    ```

**第五步：执行 SQL 脚本**

12. **找到 SQL 脚本文件**：
    - 在你的项目文件夹中，找到 `db` 文件夹
    - 打开 `db/init.sql` 文件
    - **复制全部内容**（按 `Ctrl + A` 全选，然后 `Ctrl + C` 复制）

13. **在 MySQL 中执行脚本**：
    - 回到终端，确保你在 `mysql>` 提示符下
    - **粘贴刚才复制的 SQL 脚本内容**（按 `Ctrl + V` 或右键粘贴）
    - 按回车执行
    - 等待执行完成，你会看到很多 "Query OK" 的提示

14. **（可选）添加测试数据**：
    - 如果你想添加测试数据，打开 `db/seed.sql` 文件
    - 复制全部内容
    - 在 `mysql>` 提示符下粘贴并执行

15. **退出 MySQL**：
    - 执行完成后，输入 `exit` 并按回车，退出 MySQL 连接

**✅ 完成！** 数据库表已经创建好了！

**💡 重要理解**：
- **MySQL 服务是独立的**，即使后端服务还没部署成功，你也可以连接 MySQL
- 执行 SQL 脚本只需要连接到 MySQL 服务，**不需要后端服务运行**
- 现在数据库已经准备好了，接下来配置环境变量，后端就能成功部署了

**💡 如果遇到问题：**
- **如果提示 "command not found"**：说明你的电脑没有安装 MySQL 客户端
  - **Windows**：可以下载 MySQL 客户端，或者使用方法三（客户端工具）
  - **Mac**：可以运行 `brew install mysql-client`
  - **Linux**：可以运行 `sudo apt-get install mysql-client` 或 `sudo yum install mysql`
- **如果连接失败**：
  - 检查 Railway 中的 MySQL 服务是否正在运行（状态应该是 "在线" 或 "Online"）
  - 确认你选择的是 "公共网络"（Public Network）连接方式
  - 检查防火墙是否阻止了连接
- **如果找不到密码**：
  - 在 MySQL 服务的 **"变量"**（Variables）标签页中查找 `MYSQL_ROOT_PASSWORD`
  - 如果没有，可以重置密码或创建新的 MySQL 服务

#### 🚀 方法三：使用 Railway CLI（最简单，如果你已安装 Railway CLI）

如果你已经安装了 Railway CLI 工具：

1. 在 MySQL 服务的 **"连接"**（Connect）标签页，打开连接窗口
2. 选择 **"公共网络"**（Public Network）标签页
3. 找到 **"Railway CLI 命令 `connect`"** 部分
4. 复制命令：`railway connect MySQL`
5. 在你的项目文件夹中打开终端，执行这个命令
6. Railway CLI 会自动连接到 MySQL，然后你可以执行 SQL 脚本

**💡 提示**：如果你还没有安装 Railway CLI，可以访问 https://railway.app/cli 下载安装。

#### 🛠️ 方法四：使用 MySQL 客户端工具（如果你熟悉 MySQL）

如果你已经安装了 MySQL Workbench、Navicat、DBeaver、phpMyAdmin 等工具：

1. 在 MySQL 服务的 **"连接"**（Connect）标签页，打开连接窗口
2. 选择 **"公共网络"**（Public Network）标签页
3. 找到连接信息：
   - **Host**: 例如 `xxx.proxy.rlwy.net`（从连接网址或命令中提取）
   - **Port**: 例如 `54775`（从连接网址或命令中提取）
   - **Username**: `root`
   - **Password**: 在 **"变量"**（Variables）标签页中查找 `MYSQL_ROOT_PASSWORD`
   - **Database**: `railway`（或留空，连接后选择数据库）
4. 使用你的 MySQL 客户端工具连接
5. 执行 `db/init.sql` 和 `db/seed.sql` 中的 SQL 语句

**💡 提示**：如果你不熟悉 MySQL 工具，建议使用方法二（命令行）或方法三（Railway CLI）。

### 5️⃣ 添加 Redis 服务（可选，但推荐）

**⚠️ 重要**：应用需要 Redis 服务才能正常启动。如果你不想使用 Redis，可以跳过这一步，但需要确保应用配置支持无 Redis 运行。

**详细步骤**：

1. **在 Railway 项目页面中，点击 "+ New" 按钮**
2. **选择 "Database" → "Add Redis"**

### 6️⃣ 配置后端环境变量

**这一步是告诉后端应用如何连接到数据库和 Redis。Railway 会自动提供连接信息，你只需要复制粘贴即可！**

**⚠️ 注意**：执行完 SQL 脚本后，再配置环境变量。配置完成后，后端会自动重新部署。

1. 点击你的后端服务（GitHub 部署的那个服务，不是 MySQL 或 Redis 服务）
2. 点击 **"Variables"** 标签页
3. 点击 **"+ New Variable"**，逐个添加以下变量：

**必需变量（6 个）**：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `SPRING_PROFILES_ACTIVE` | `mysql` | 使用 MySQL 数据库 |
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://${{MySQL.MYSQLHOST}}:${{MySQL.MYSQLPORT}}/${{MySQL.MYSQLDATABASE}}?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC` | 数据库连接地址（Railway 自动替换） |
| `SPRING_DATASOURCE_USERNAME` | `${{MySQL.MYSQLUSER}}` | 数据库用户名（Railway 自动替换） |
| `SPRING_DATASOURCE_PASSWORD` | `${{MySQL.MYSQLPASSWORD}}` | 数据库密码（Railway 自动替换） |
| `JWT_SECRET` | `libra-bms-secret-key-libra-bms-secret-key-libra-bms` | JWT 密钥（用于用户登录） |
| `PORT` | `8080` | 应用端口 |

**Redis 变量（如果添加了 Redis 服务，需要添加这 3 个）**：

| 变量名 | 值 | 说明 |
|--------|-----|------|
| `SPRING_DATA_REDIS_HOST` | `${{Redis.REDISHOST}}` | Redis 主机地址（Railway 自动替换） |
| `SPRING_DATA_REDIS_PORT` | `${{Redis.REDISPORT}}` | Redis 端口（Railway 自动替换） |
| `SPRING_DATA_REDIS_PASSWORD` | `${{Redis.REDISPASSWORD}}` | Redis 密码（Railway 自动替换，如果没有密码可以留空） |

**💡 重要提示**：
- `${{MySQL.XXX}}` 和 `${{Redis.XXX}}` 是 Railway 的特殊语法，Railway 会自动将这部分替换为真实的连接信息
- 你不需要知道数据库和 Redis 的具体地址、用户名、密码，Railway 会自动处理
- 如果**没有添加 Redis 服务**，可以不添加 Redis 相关的环境变量，应用会跳过 Redis 配置
- 添加完所有变量后，Railway 会自动重新部署应用
- **此时部署应该会成功**，因为数据库已经初始化好了！

### 7️⃣ 获取后端 API 地址

1. 点击后端服务
2. 点击 **"Settings"** 标签页
3. 在 **"Domains"** 部分，点击 **"Generate Domain"**
4. 复制生成的域名（例如：`libra-backend-production.up.railway.app`）
5. **这就是你的后端地址！** 完整 URL：`https://libra-backend-production.up.railway.app`

### 8️⃣ 配置 Vercel 前端

1. 访问 Vercel Dashboard：https://vercel.com/dashboard
2. 进入你的项目：`libra-library-system-mga2`
3. 点击 **"Settings"** → **"Environment Variables"**
4. 添加新变量：
   - **Name**: `VITE_APP_BASE_API`
   - **Value**: 你的 Railway 后端地址（例如：`https://libra-backend-production.up.railway.app`）
   - **Environment**: 全选（Production, Preview, Development）

## ❓ 常见疑问解答

### Q1: 我需要在本地安装 MySQL 吗？
**A:** 不需要！Railway 会在云端自动创建和管理 MySQL 数据库。你只需要在 Railway 网页上点击按钮添加数据库即可。

### Q2: 数据库连接信息在哪里？
**A:** Railway 会自动提供。当你添加 MySQL 数据库后，Railway 会自动生成连接信息，并通过 `${{MySQL.XXX}}` 环境变量自动注入到后端应用中。你不需要手动查找或配置。

### Q3: 我需要知道数据库的密码吗？
**A:** 不需要！Railway 会自动管理密码，并通过环境变量传递给后端应用。你只需要在环境变量中使用 `${{MySQL.MYSQLPASSWORD}}`，Railway 会自动替换。

### Q4: 执行 SQL 脚本很复杂吗？
**A:** 不复杂！你只需要：
1. 在 Railway 上复制 MySQL 连接命令
2. 在终端中执行命令连接数据库
3. 复制粘贴 `db/init.sql` 的内容并执行
4. 完成！

### Q5: 如果我不懂 SQL 怎么办？
**A:** 没关系！你只需要复制粘贴 SQL 脚本内容即可，不需要理解 SQL 语法。脚本会自动创建所有需要的数据表。

## 🐛 常见问题

### ❌ 后端启动失败

**问题**：Railway 日志显示启动失败

**解决**：
1. 检查环境变量是否正确配置
2. 确认数据库连接信息（特别是 `SPRING_DATASOURCE_URL`）
3. 查看 Railway 的 Logs 标签页，找到具体错误信息

### ❌ 数据库连接失败

**问题**：后端无法连接数据库

**解决**：
1. 确认 MySQL 服务已启动（Railway 中显示为 Running）
2. 检查环境变量是否正确配置：
   - `SPRING_DATASOURCE_URL` 中的 `${{MySQL.XXX}}` 是否正确
   - 所有环境变量是否都已添加
3. 确认数据库已创建（Railway 会自动创建数据库，但你需要执行 `init.sql` 创建表）
4. 查看 Railway 的 Logs，找到具体的错误信息

**常见错误**：
- 如果看到 "Table doesn't exist"，说明还没有执行 `init.sql`，请回到步骤 5
- 如果看到 "Access denied"，检查环境变量中的用户名和密码是否正确

### ❌ 前端 502 错误

**问题**：前端显示 502 Bad Gateway

**解决**：
1. 确认 `VITE_APP_BASE_API` 环境变量已设置
2. 确认后端地址可以访问（在浏览器中打开）
3. 确认后端服务正在运行（Railway 中显示为 Running）
4. 重新部署前端（Redeploy）

### ❌ CORS 跨域错误

**问题**：浏览器控制台显示 CORS 错误

**解决**：
- 项目已添加 CORS 配置，应该不会有这个问题
- 如果仍有问题，检查后端日志确认 CORS 配置已加载
